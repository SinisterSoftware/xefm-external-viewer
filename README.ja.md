# External Viewers

ファイル一覧でカーソル位置のファイルを外部ビューアーで開く、Windows 向け XeFM 拡張機能です。XeFM 1.13.0 以降が必要です。

## インストール

XeFM のコマンドラインで次を実行します。

```text
xefm ext install github:SinisterSoftware/xefm-external-viewer
```

インストール時に依存パッケージの同期を求められたら許可してください。後から同期する場合は次を実行します。

```text
xefm deps sync
```

この拡張機能は、Office の読み取り専用連携に使う Python パッケージ `pywin32` を必要とします。SumatraPDF、mpv、Microsoft Office は拡張機能には含まれず、必要に応じて別途インストールしてください。これらのビューアーは任意で、どれかが見つからなくても拡張機能全体が無効にならない設計です。

## 標準の使い方

ファイル一覧で対象ファイルにカーソルを合わせて **Enter** を押すと、拡張機能のルールに一致した場合は対応する外部ビューアーで開きます。標準ルールは次のとおりです。

| ファイル | 開くアプリ |
| --- | --- |
| `.pdf`, `.epub` | SumatraPDF（`sumatrapdf`） |
| `.xls` | Microsoft Excel |
| `.doc` | Microsoft Word |
| `.ppt` | Microsoft PowerPoint |
| `.ts`, `.mp4`, `.mpg`, `.vob`, `.mov`, `.flac`, `.wv`, `.m4a` | mpv |

`sumatrapdf` と `mpv` は PATH から起動します。PATH に登録していない場合は、後述の設定で実行ファイルの絶対パスを指定してください。Office のルールは旧形式の `.xls`、`.doc`、`.ppt` のみが対象です。Office がインストールされ、COM オートメーションから利用できる必要があります。Office のファイルは読み取り専用で開かれます。新しい Office 形式（`.xlsx`、`.docx`、`.pptx` など）は標準ルールの対象外です。

拡張機能は XeFM の `file_open` フックで Enter の処理に参加します。ファイルを開く処理に成功すると、そのフックはファイルを処理済みとして通知します。形式がルールに一致しない場合や外部ビューアーの起動に失敗した場合は、エラーを記録して処理を譲り、XeFM の他のフックや通常のファイル処理に続けてもらいます。失敗時に XeFM 内蔵ビューアーで表示できるかどうかはファイル形式によります。

## `V` アクション

拡張機能は `external-viewer.view-file` アクションを提供し、標準キーとして `V` を提案します。既に `V` が別のアクションに割り当てられている場合、提案は適用されないことがあります。その場合は XeFM のコマンドパレットから **View the focused file with its external viewer** を実行するか、`~/.xefm/config.py` の既存の `Config.KEY_BINDINGS` に明示的に追加します。

特に `afx` キーマップでは、XeFM 標準の `view_file`（内蔵ビューアー）も `V` を使います。外部ビューアーに `V` を割り当てる場合は、内蔵ビューアーの割り当ても別のキーに移すか、不要なら `view_file` を空のキーリストで解除してください。ほかのキーマップでは既定キーが異なるため、現在の割り当てを確認してから設定します。

```python
class Config:
    KEY_BINDINGS = {
        'external-viewer.view-file': ['V'],
    }
```

既に `KEY_BINDINGS` がある場合は、上記の内容で置き換えず、既存の辞書にアクションの行を追加してください。`V` が別のアクションと競合する場合は、そちらの割り当てを別のキーに移すか、このアクションに競合しないキーを設定します。キーの表記や割り当ては XeFM のキーマップ設定に従います。

このアクションは、カーソル位置のファイルについて外部ビューアーを試します。ルールに一致しない、起動に失敗するなどの場合は XeFM の通常の `view_file` 処理にフォールバックします。`.eml` / `.msg` では利用可能なら Mail Archive の `mail_archive.open`、`.db` / `.sqlite` / `.sqlite3` / `.db3` では利用可能なら SQLite Archive の `sqlite_archive.open` も試します。これらの形式は外部ビューアーの標準ルールには含まれていません。アーカイブ用アクションが利用できない場合、または実行後にペインの場所が変わらない場合は通常のビューアー処理に進みます。

## ビューアーの設定

ユーザー設定ファイル `~/.xefm/config.py` に、`Config` クラスの外側（トップレベル）で `ExternalViewerConfig` クラスを定義します。設定の既定値は `xefm ext settings external-viewer` で確認できます。

```python
class ExternalViewerConfig:
    VIEWERS = [
        {'pattern': ['*.pdf', '*.epub'],
         'command': ['sumatrapdf']},
        {'pattern': '*.xls', 'command': 'office:excel'},
        {'pattern': '*.doc', 'command': 'office:word'},
        {'pattern': '*.ppt', 'command': 'office:powerpoint'},
        {'pattern': ['*.ts', '*.mp4', '*.mpg', '*.vob', '*.mov',
                     '*.flac', '*.wv', '*.m4a'],
         'command': ['mpv']},
    ]
```

この例は既定のルールを再掲しています。`VIEWERS` を設定すると既定リスト全体が置き換わるため、一部だけ変更したい場合も、残したいルールを含めてリスト全体を記述してください。ルールは上から順に照合され、最初に一致したものが使われます。パターン照合は大文字と小文字を区別しません。ルールを削除すると、その形式はこの拡張機能では処理せず、XeFM または他の拡張機能に任せます。`VIEWERS = []` にすると、この拡張機能による外部ビューアーへの振り分けをすべて無効にできます。

各ルールには `pattern` と `command` が必要です。

- `pattern`: ファイル名に照合する glob 文字列、または glob 文字列の空でないリストです。たとえば `*.pdf` や `['*.pdf', '*.epub']` のように指定します。
- `command`: 次のいずれかを指定します。
  - `['アプリの実行ファイル', '引数']` のような空でない引数リスト。対象ファイルのパスは末尾に1つの引数として追加されます。プレースホルダーは不要です。XeFM のターミナルには接続されないため、GUI アプリを指定してください。
  - `'office:excel'`、`'office:word'`、`'office:powerpoint'` のいずれか。対応する Microsoft Office アプリで開きます。
  - `None`。Windows のファイル関連付けに従って開きます。
  - `fn(ctx, path)` 形式の Python 呼び出し可能オブジェクト。明示的に `False` を返すと、そのルールは開く処理を引き受けません。

たとえば SumatraPDF を PATH に登録していない場合は、実行ファイルの絶対パスをリストに指定できます。

```python
{'pattern': '*.pdf',
 'command': [r'C:\Program Files\SumatraPDF\SumatraPDF.exe']},
```

カスタムルールは `VIEWERS` のリスト全体を置き換えることに注意してください。既定の他の形式も引き続き開く場合は、そのルールも同じリストに含めます。

## 他の拡張機能との連携と注意点

XeFM は、ある拡張機能の `file_open` フックがファイルを処理済みとして返した後も、登録されている他のフックを実行します。そのため、別の拡張機能が扱うファイル形式に独自ルールを重ねると、複数の拡張機能が同じファイルを開いたり、ペインを移動したりする可能性があります。Mail Archive や SQLite Archive などが処理するファイルには、重複するルールを追加しないでください。

リモートやアーカイブ内の仮想ファイルを外部アプリに渡すときは、一意な名前の一時ディレクトリにコピーしてから起動します。コピーは XeFM 終了時に削除され、元のファイルへ変更を書き戻しません。ビューアーを開いたまま XeFM を終了すると、ビューアーが参照している一時ファイルが消えることがあります。大きなファイルやリモートファイルはコピーに時間がかかる場合があります。

外部アプリの起動後に、そのアプリ内で発生したエラーは検出できません。そのため、起動そのものが成功した後にビューアー側で読み込みに失敗しても、XeFM の通常表示にはフォールバックしません。

## トラブルシューティング

- **外部アプリが見つからない:** `sumatrapdf` や `mpv` が PATH から起動できるか確認してください。PATH を使わない場合は、`command` に実行ファイルの絶対パスを指定します。
- **Office ファイルが開かない:** Microsoft Office がインストールされ、COM オートメーションから利用できることを確認してください。`pywin32` の依存パッケージも同期してください。対象は `.xls`、`.doc`、`.ppt` の旧形式です。
- **`V` を押しても外部ビューアーが起動しない:** `V` が別のアクションに割り当てられていないか確認してください。競合時はコマンドパレットからアクションを実行するか、`KEY_BINDINGS` で別のキーを指定します。
- **カスタムルールが反映されない:** クラス名が `ExternalViewerConfig` であること、`Config` クラスの外に記述されていること、`VIEWERS` に残したいルールがすべて含まれていることを確認してください。ルールの順序も確認してください。
- **失敗後にファイルが開かない:** XeFM のログやエラーメッセージを確認してください。拡張機能が起動前に失敗すると処理を譲りますが、XeFM 内蔵ビューアーがそのファイル形式に対応しているとは限りません。

設定を変更した後は XeFM の **Tools > Reload Configuration** を実行するか、XeFM を再起動してください。

## 開発

```text
xefm ext check .
python -m pytest tests
```

テストは模擬コンテキストと起動処理を使い、XeFM や外部アプリを起動しません。
